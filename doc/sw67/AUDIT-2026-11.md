# 6|7 World Studio: feature audit and extension (November 2026)

This report answers two requests from 18 November 2026: the audit and
extension of the Basic and DJ & Hosting features, and Party Contacts with the
Sound Equalizer and DJ Sound Check.

## How to read the statuses

- **Working**: built, its logic tested, and its window written and registered.
- **Partial**: some of what was asked works, and the rest is named.
- **Missing**: not built.
- **Blocked**: cannot be built until a named dependency or decision exists.

**What "verified" means here.** All the rules behind each feature live in
`indra/sw67core`, which builds and runs on its own. That code is tested with
Catch2 (165 test cases, 3,866 assertions, all passing). The viewer windows are
compiled only by the GitHub Actions builds for Windows x64 and Linux x64.

I could not run the viewer itself or log in to Second Life from this
environment. So nothing below was clicked through in-world. Everywhere it
says "tested", that means the core tests, not a live session. The in-world
checks to do are listed at the end.

Every window below opens from **Me > 6|7 Studio** in the top menu bar.

### Which audio sources and broadcast integrations were verified

| Source | Equalizer | Meter | Why |
|---|---|---|---|
| World sounds (objects, ambient) | Yes | Yes | These are mixed by the viewer's own engine (FAudio), where I attached the filter and a meter. |
| Interface sounds | Yes | Yes | Same engine, separate group. |
| Parcel music | No | No | It plays in a separate media plugin process, and the viewer never receives its sound. |
| Voice chat | No | No | WebRTC plays it outside the viewer's mixer. |
| Outgoing broadcast | No | No | DJs broadcast from their own app (for example a streaming encoder). This viewer sends no audio stream, so the switch reads "Monitor Only". |

Headphone preview is the same as local playback, because the viewer has one
audio output.

**Something I found along the way.** The audio library's built-in equalizer
and its master limiter (FAudio's FXEQ and FXMasteringLimiter) contain no
processing upstream, so the viewer's existing "limiter" does nothing. I wrote
our own filter effect instead of using FXEQ. Upstream Alchemy should hear about
the limiter.

## Blockers and what each one needs

1. **LSL drafting:** PR #7 merged on 18 Nov and is live on the gateway.
2. **6|7 Phone Companion:** built as a web app on the King Jahmir gateway
   (see the table). PR #8 merged on 18 Nov and is live. Push notifications
   need a native app; the calendar reminder stands in for them.
3. **Live co-host sharing of guest lists:** needs a 6|7 account service.
   Lists are shared by exporting a file. RSVPs now come from the Phone
   Companion's RSVP page as well as from a file.
4. **Director video export:** done. Director writes Motion JPEG .avi files
   itself, so no encoder is bundled. Files are larger than MP4; an MP4 option
   (through the system's own encoder on Windows and macOS) can come later.
5. **AI mesh generation and video processing:** need an AI provider for each
   and the credit system (Milestone 5 billing).
6. **Billing:** needs a payment provider and the billing service. Nothing is
   charged or simulated today.
7. **Parcel music and voice EQ:** these would need audio routed back from the
   media plugin and from WebRTC. That is large engine work, so for now the
   window states the limitation.

## Questions for Linden Lab

- **IM limits.** What are the exact limits for one resident sending IMs to
  many recipients? 6|7 caps a send at 40 people, 2 seconds apart, sent only
  after the host confirms. We want written confirmation that this is
  acceptable and won't be treated as spam under the Third Party Viewer
  policy.
- **Group-style announcements from a viewer feature.** The TPV policy covers
  automated messaging. Is a host-approved, paced send to people who opted in
  acceptable, or does each message need its own click?
- **Mesh check.** Can a viewer pre-check that only advises (it never blocks
  the official uploader, and never changes upload fees) describe Second
  Life's limits in its own words?
